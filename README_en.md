## Features

| Feature | Description |
|---------|-------------|
| **Framework-managed delivery** | Reminder text is generated by AstrBot's main Agent with the target session's persona and history, then sent through `send_message_to_user`. Plain text only |
| **Daily morning briefing** | Weather + next 24 hours of schedules (local and Apple) + Notion to-dos in one message |
| **Habit reminders** | Bath, sleep and water reminders with configurable times and switches |
| **Schedule reminders** | Pushed N minutes before a schedule starts, using the schedule note as context |
| **LLM schedule management** | Add, delete, list and update schedules in natural language |
| **Two-way Apple Calendar sync** | iCloud CalDAV read and write with deduplication and incremental updates |
| **Notion to-do sync** | DDL countdown in the morning briefing (days left / due today / overdue) |

## How it works

Reminders are delivered by AstrBot's proactive Agent mechanism. The plugin only assembles the data and a task note at the right time, then hands the note to an `active job`. The framework wakes the main Agent of the target session, which writes the message with that session's persona and history and sends it via `send_message_to_user`.

Tone therefore follows the persona you configured for the bot; the plugin has no separate persona setting.

All pushes are plain text. A failed delivery is treated as lost for that occurrence; there is no automatic retry and no duplicate catch-up.

### Daily morning briefing

Pushed every morning at a configurable time:

- Current weather and forecast
- Local and Apple schedules within 24 hours from the push time, merged and deduplicated
- Notion to-dos with DDL countdown
- All-day schedules count only on the day of the briefing

The built-in prompts are short task instructions with data; a custom prompt replaces the whole built-in template.

### Habit reminders

| Habit | Default time | Notes |
|-------|--------------|-------|
| Bath | 22:00 | Configurable |
| Sleep | 23:00 | Configurable |
| Water | Every 90 min | Between 09:30 and 21:30 |
| Schedule reminder | N minutes before | Disabled by default |

### Apple iCloud Calendar two-way sync

**Read (Apple to local):**
- Pulls iCloud events into local storage on a timer
- Syncs additions, changes and deletions, with Apple Calendar as the source of truth

**Write (local to Apple):**
- Schedules created through the bot are written to the configured Apple calendar
- Event UIDs are stored for later matching and deduplication

**Required fields:**
- `username` — Apple ID email (for example `you@icloud.com`)
- `app_password` — an **app-specific password** from [appleid.apple.com](https://appleid.apple.com), not your login password
- `calendar_id` — target calendar UUID; leave empty for the first one. The available values are listed in the log as `name → UUID`, or take the UUID segment from `.../calendars/<UUID>/`
- `caldav_host` — CalDAV host; defaults to `caldav.icloud.com`. For mainland China accounts use `caldav.icloud.com.cn`; if that still fails, use your partition host such as `pXX-caldav.icloud.com.cn` from the iCloud web calendar sharing link

### Notion to-do sync

Notion to-dos appear in the morning briefing with a DDL countdown. Access goes through Maton Gateway.

## Quick start

### 1. Install

AstrBot WebUI → Plugin Market → search for `schedule_assistant`

> **Note:** Dependencies are declared in `requirements.txt` (`aiohttp`, `python-dateutil`). AstrBot checks and installs missing dependencies when loading the plugin.

### 2. Fill in the session list

Send `/sid` in the session (private chat or group) that should receive reminders, and note the UMO it returns. Then open the plugin configuration → **Basic Settings** → `user_umos` and add one line per session:

```
qq:FriendMessage:123456789
qq:GroupMessage:987654321
```

`platform:message_type:session` (UMO format). Malformed entries are skipped with one warning at startup.

A group is treated as an independent user: members share one schedule list, and morning, bath, sleep and water pushes all go to the group. Reminders and tools operate on the group as a whole, so make sure members know.

### 3. Optional: Notion

1. Connect Notion through [Maton](https://www.maton.ai/) (OAuth2) and generate a **Maton API Key**
2. Fill `maton_api_key` under **External Services**, and list databases in `notion_db_ids` (for example `Tasks:xxx`, `Reading:yyy`)

> **Note:** Notion data goes through the third-party gateway `gateway.maton.ai`, not the official Notion API. The `maton_api_key` is sent to that gateway, which can read the title, status and due date fields of the databases you specify.

## Configuration

### Basic settings

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `user_umos` | list | `[]` | Session UMOs that receive pushes, one `platform:message_type:session` per line |

### Schedule reminder settings

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enable_schedule_reminder` | bool | `false` | Enable schedule reminders |
| `schedule_reminder_minutes` | int | `10` | Minutes before the schedule to push; all-day schedules are skipped |

### Habit reminder settings

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enable_morning_report` | bool | `true` | Morning briefing switch |
| `morning_report_time` | string | `09:00` | Briefing time (HH:MM) |
| `enable_bath_reminder` | bool | `true` | Bath reminder switch |
| `bath_time` | string | `22:00` | Bath reminder time |
| `enable_sleep_reminder` | bool | `true` | Sleep reminder switch |
| `sleep_time` | string | `23:00` | Sleep reminder time |
| `enable_water_reminder` | bool | `true` | Water reminder switch |
| `water_interval` | int | `90` | Water interval in minutes |
| `water_start_time` | string | `09:30` | First water reminder |
| `water_end_time` | string | `21:30` | Last water reminder |

### Calendar sync settings

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `enable_apple_calendar_sync` | bool | `false` | Two-way Apple Calendar sync |
| `apple_calendar_sync_interval` | int | `30` | Sync interval in minutes |
| `apple_calendar.username` | string | - | Apple ID email |
| `apple_calendar.app_password` | string | - | App-specific password |
| `apple_calendar.caldav_host` | string | - | CalDAV host; see above for China-specific hosts |
| `apple_calendar.calendar_id` | string | - | Target calendar UUID; empty means the first one |
| `webcal_urls` | list | `[]` | WebCal subscription URLs |

> **WebCal safety:** `webcal_urls` accepts only public `https://` feeds (`webcal://` is converted). `localhost`, private networks (`192.168.x`, `10.x`) and cloud metadata addresses (`169.254.169.254`) are rejected to prevent SSRF.

### External services

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `maton_api_key` | string | `""` | Maton API Key (required for Notion) |
| `notion_db_ids` | list | `[]` | Databases in the form `Task:xxx`, `Reading:yyy` |
| `weather_api_key` | string | `""` | Seniverse API key |
| `weather_city` | string | `Beijing` | Weather city |

### Reminder prompts

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `prompt_morning` | string | `""` | Morning prompt. Placeholders: `{date} {weekday} {weather_current} {weather_forecast} {agenda} {notion_todos}` |
| `prompt_bath` | string | `""` | Bath prompt. Placeholders: `{current_time}` |
| `prompt_sleep` | string | `""` | Sleep prompt. Placeholders: `{current_time}` |
| `prompt_water` | string | `""` | Water prompt. Placeholders: `{current_time}` |
| `prompt_schedule` | string | `""` | Schedule prompt. Placeholders: `{item_title} {time_label} {ahead_label} {item_context}` |

> Empty means the built-in prompt (data block, writing requirement and output requirement). A non-empty value takes over completely: the plugin appends no writing or output constraints. Pushes are plain text, so write rules such as "output the body only, never mention the system" yourself.

## LLM tools

The plugin registers four LLM tools. The model decides when to call them; you just speak naturally.

> **Time formats:** ISO 8601. Use `2026-09-10 14:30` for timed entries and `2026-09-10` with `all_day=true` for all-day entries. Start times cannot be in the past, and years cannot exceed 2100.

```
User: add a team meeting tomorrow at 9
-> create_schedule(title=team meeting, start=2026-09-11 09:00)
   Created "team meeting", time: 09-11 09:00 ✅

User: meeting from 9 to 11 tomorrow
-> create_schedule(title=meeting, start=2026-09-11 09:00, end=2026-09-11 11:00)
   Created "meeting", time: 09-11 09:00-11:00 ✅

User: all-day offsite the day after tomorrow
-> create_schedule(title=offsite, start=2026-09-12, all_day=true)
   Created "offsite", time: 09-12 all day ✅

User: what's on this week
-> list_schedules(days=7)
   📋 Next 7 days (3 items):

   ━━━ 08-17 Mon ━━━
     ⏰ 09:00 │ team meeting

User: delete tomorrow's reading group
-> delete_schedule(title_keyword=reading group)
   Deleted "reading group" ✅
```

### create_schedule

| Parameter | Type | Description |
|-----------|------|-------------|
| `title` | string | **Required**, schedule title |
| `start` | string | **Required**, ISO 8601 start time (`2026-09-10 14:30`); for all-day entries a date such as `2026-09-10` |
| `end` | string? | Optional ISO 8601 end time; omitted means a single point (Apple gets one hour) |
| `all_day` | bool? | Whether this is an all-day entry |
| `description` | string? | Optional note |

### delete_schedule

| Parameter | Type | Description |
|-----------|------|-------------|
| `schedule_id` | string? | Exact schedule ID |
| `title_keyword` | string? | Title keyword (fuzzy match) |

### list_schedules

| Parameter | Type | Description |
|-----------|------|-------------|
| `days` | int? | Days ahead, default 7 |

### update_schedule

| Parameter | Type | Description |
|-----------|------|-------------|
| `schedule_id` | string? | Exact schedule ID |
| `title_keyword` | string? | Title keyword (fuzzy match) |
| `new_title` | string? | New title |
| `new_start` | string? | New start time (ISO 8601) |
| `new_end` | string? | New end time (ISO 8601), requires `new_start` |
| `new_all_day` | bool? | Whether to make it an all-day entry |
| `new_description` | string? | New note |
