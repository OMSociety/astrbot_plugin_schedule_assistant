|------|------|
| **Ежедневная утренняя рассылка** | Погода + расписание на день + задачи Notion + определение позднего отбоя — вся информация для подъёма в одном сообщении |

## Обзор возможностей

### Ежедневная утренняя рассылка
Каждое утро автоматически приходит сообщение (время настраивается) — вся информация для подъёма в одном сообщении:

<img src="https://raw.githubusercontent.com/OMSociety/astrbot_plugin_schedule_assistant/main/docs/briefing_example.png" alt="Пример утренней рассылки" width="480" />

### Напоминания о привычках

| Привычка | Время по умолчанию | Описание |
|------|---------|------|
| Напоминание о душе | 22:00 | Время напоминания настраивается |
| Напоминание о сне | 23:00 | Умное укладывание, при опоздании — с подколами |
| Напоминание о воде | Каждые 90 минут | Напоминания в интервале 9:30–21:30 |
| Умное напоминание о расписании | За N минут | Напоминания на естественном языке, **сгенерированные LLM**, с учётом контекста |

### Двусторонняя синхронизация с календарём Apple iCloud

**Чтение (Apple → локально):**
- Периодически подтягивает события календаря iCloud в локальное хранилище
- Автоматически синхронизирует добавление / изменение / удаление; эталоном является календарь Apple

**Запись (локально → Apple):**
- Расписание, добавленное через бота, автоматически записывается в указанный календарь Apple
- UID событий сохраняются для последующего распознавания и дедупликации при синхронизации

**Что нужно для подключения:**
- `username` — почта Apple ID (например, `xxx@icloud.com`)
- `app_password` — **пароль приложения** (создаётся на [appleid.apple.com](https://appleid.apple.com), это не пароль для входа)
- `calendar_id` — UUID целевого календаря; если оставить пустым, берётся первый. UUID можно скопировать из адреса CalDAV-сервера календаря Apple: адрес имеет вид `…/calendars/<UUID>/`, возьмите сегмент UUID и вставьте его

### Синхронизация задач Notion
Задачи Notion перечисляются в ежедневной утренней рассылке с обратным отсчётом до дедлайна (осталось N дней / истекает сегодня / просрочено). Требуется предварительно настроить Maton Gateway как промежуточный слой.

### Markdown-рендеринг
Все запланированные рассылки (утренняя / привычки / напоминания о расписании) проходят через единый конвейер рендеринга с автоматическим откатом по платформам:
- **native** — платформы с нативным разбором md (qq_official, discord, telegram и др.) получают сообщение как есть
- **plain** — платформы без нативной поддержки md автоматически очищаются до обычного текста

Нативные таблицы QQ автоматически рендерятся как выровненные строки, без дополнительной настройки; можно отключить или принудительно переключить в конфигурации.

## Быстрый старт

### Шаг 1: Установка Schedule Assistant

AstrBot WebUI → Маркетплейс плагинов → найдите `schedule_assistant`

> **Примечание:** Зависимости указаны в `requirements.txt` плагина (`apscheduler` / `aiohttp` / `python-dateutil`): AstrBot сам проверяет и доустанавливает недостающие при загрузке и установке плагина, поэтому вручную устанавливать их обычно не нужно.

### Шаг 2: Минимальная конфигурация (запуск всех запланированных напоминаний)

Достаточно заполнить одну строку в WebUI: конфигурация плагина → **Базовые настройки** → `user_ids`:

```
IDПлатформы:FriendMessage:UserID
```

Формат `IDПлатформы:ТипСессии:IDПользователя` (формат UMO) — одна строка решает, «кому напоминать + с какой платформы отправлять». Можно указать просто номер QQ — сообщение будет отправлено как личный чат автоматически.

### Шаг 3 (необязательно): настройка синхронизации с Notion

1. Подключите Notion на [Maton](https://www.maton.ai/) (через OAuth2) и сгенерируйте **Maton API Key**
2. В настройках плагина → **Внешние сервисы** укажите `maton_api_key` и задайте базы данных для чтения через `notion_db_ids` (например, `работа:xxx`, `чтение:yyy`)

> **Внимание:** Задачи Notion получаются через сторонний шлюз `gateway.maton.ai` (не напрямую через официальный API Notion): `maton_api_key` отправляется этому третьему лицу в заголовке запроса, и оно может читать такие поля указанных вами баз, как заголовок, статус и срок.

## Описание параметров конфигурации

### Базовые настройки

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `persona_id` | string | `""` | ID личности LLM (соответствует `persona_id` в файле конфигурации); если пусто, берётся автоматически из сессии |
| `user_nickname` | string | `""` | Никнейм пользователя; если пусто, в рассылках используется обращение «хозяин» |
| `user_ids` | list | `[]` | Список ID пользователей, по одному на строку (номер QQ или UID платформы); формат UMO (`IDПлатформы:ТипСессии:IDПользователя`) заодно задаёт маршрутизацию по платформе |

### Настройки напоминаний о расписании

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `enable_schedule_reminder` | bool | `false` | Переключатель умных напоминаний о расписании через LLM (по умолчанию выключено) |
| `schedule_reminder_minutes` | int | `10` | За сколько минут до начала напоминать (для событий на весь день (all-day) напоминания не отправляются) |
| `schedule_reminder_check_interval` | int | `5` | Интервал сканирования напоминаний о расписании (в минутах); рекомендуется 1/3–1/2 от времени опережения (например, 3–5 минут при опережении в 10 минут), минимум 2 минуты и не больше времени опережения |

### Настройки напоминаний о привычках

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `enable_morning_report` | bool | `true` | Переключатель утренней рассылки |
| `morning_report_time` | string | `09:00` | Время отправки утренней рассылки (HH:MM) |
| `enable_bath_reminder` | bool | `true` | Переключатель напоминания о душе |
| `bath_time` | string | `22:00` | Время напоминания о душе |
| `enable_sleep_reminder` | bool | `true` | Переключатель напоминания о сне |
| `sleep_time` | string | `23:00` | Время напоминания о сне |
| `enable_water_reminder` | bool | `true` | Переключатель напоминания о воде |
| `water_interval` | int | `90` | Интервал напоминаний о воде (в минутах) |
| `water_start_time` | string | `09:30` | Время начала напоминаний о воде |
| `water_end_time` | string | `21:30` | Время окончания напоминаний о воде |

### Настройки синхронизации календаря

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `enable_apple_calendar_sync` | bool | `false` | Переключатель двусторонней синхронизации с календарём Apple |
| `apple_calendar_sync_interval` | int | `30` | Интервал синхронизации с календарём Apple (в минутах) |
| `apple_calendar.username` | string | - | Почта Apple ID |
| `apple_calendar.app_password` | string | - | **Пароль приложения** (не пароль для входа) |
| `apple_calendar.calendar_id` | string | - | UUID целевого календаря; если пусто, берётся первый; UUID копируется из адреса CalDAV-сервера календаря Apple (`…/calendars/<UUID>/`) |
| `webcal_urls` | list | `[]` | Ссылки на общие календари WebCal |

> **Безопасность подписки WebCal**: `webcal_urls` принимает только публичные адреса подписки `https://` (`webcal://` автоматически преобразуется в `https://`). Плагин отклоняет адреса вроде `localhost`, внутренней сети (например, `192.168.x` / `10.x`) и облачных метаданных (`169.254.169.254`) для защиты от SSRF. Не указывайте внутренние или локальные адреса.

> Запись управляется единым переключателем верхнего уровня `enable_apple_calendar_sync`; после включения расписание, созданное/удалённое локально, автоматически синхронизируется с календарём Apple.

### Настройки внешних сервисов

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `maton_api_key` | string | `""` | Maton API Key (обязателен для функций Notion) |
| `notion_db_ids` | list | `[]` | Список ID баз данных Notion, формат: `["работа:xxx", "чтение:yyy"]` — префикс — произвольное название категории на ваш выбор |
| `weather_api_key` | string | `""` | API-ключ погоды Seniverse ([seniverse.com](https://seniverse.com)) |
| `weather_city` | string | `北京` | Город для запроса погоды (по умолчанию: Пекин) |

### Настройки рендеринга сообщений

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `markdown_enabled` | bool | `true` | Глобальный переключатель рендеринга Markdown; при выключении откат к обычному тексту |
| `markdown_native_platforms` | list | `[]` | Дополнительные названия типов платформ с нативным разбором Markdown (ID экземпляров не работают) |
| `qq_markdown_enabled` | bool | Пусто | Переключатель для QQ: пусто — следовать глобальной настройке; `false` — принудительно отключить нативный md для QQ |

### Шаблоны промптов напоминаний

| `prompt_sleep` | string | `""` | Шаблон напоминания о сне. Плейсхолдеры: `{current_time} {default_time} {is_late} {history}` |
| `prompt_water` | string | `""` | Шаблон напоминания о воде. Плейсхолдеры: `{current_time} {history}` |
| `prompt_schedule` | string | `""` | Шаблон напоминания о расписании. Плейсхолдеры: `{item_title} {time_label} {ahead_label} {item_context} {conv_history}` |

> Если шаблон оставлен пустым, используется встроенный по умолчанию (см. `prompt_config.py`); заполните его, чтобы настроить тон напоминаний, поддерживаются плейсхолдеры вида `{имя_переменной}`.

## Инструменты, вызываемые LLM

Плагин регистрирует 4 инструмента LLM; модель сама определяет, когда их вызывать, — просто опишите задачу на естественном языке:

> **Форматы времени**: числовой/ISO («2024-01-15 14:30», «2024-01-15 09:00-11:00», «2024-01-16») или китайский естественный язык («明天9点», «明天9点到11点», «明天全天»); одна дата = весь день.

```
Пользователь: Добавь расписание — завтра планёрка в 9 утра
🤖 → create_schedule(title=Планёрка, datetime_str=2024-01-15 09:00)
    Запись «Планёрка» создана, время: 01-15 09:00 ✅

Пользователь: Планёрка 2024-01-15 с 09:00 до 11:00
🤖 → create_schedule(title=Планёрка, datetime_str=2024-01-15 09:00-11:00)
    Запись «Планёрка» создана, время: 01-15 09:00-11:00 ✅

Пользователь: Тимбилдинг 2024-01-16, весь день
🤖 → create_schedule(title=Тимбилдинг, datetime_str=2024-01-16)
    Запись «Тимбилдинг» создана, время: 01-16 весь день ✅

Пользователь: Перенеси встречу с 15:00 на 16:00
🤖 → update_schedule(title_keyword=встреча, new_datetime=2024-01-15 16:00)
    Запись изменена: время — 16:00 ✅

Пользователь: Покажи расписание на неделю
🤖 → list_schedules(days=7)
    📋 Расписание на ближайшие 7 дней (всего 3):
    ━━━ 08-17 Пн ━━━
      ⏰ 09:00 │ Планёрка
      ...

Пользователь: Удали завтрашний книжный клуб
🤖 → delete_schedule(title_keyword=книжный клуб)
    Запись «Книжный клуб» удалена ✅
```

### create_schedule
Создаёт новую запись расписания.

| Параметр | Тип | Описание |
|------|------|------|
| `title` | string | **Обязательно**, заголовок/содержание записи |
| `datetime_str` | string | **Обязательно**, время в числовом/ISO формате («2024-01-15 14:30», «2024-01-15 09:00-11:00») или на китайском естественном языке («明天9点», «明天9点到11点», «明天全天»); одна дата = весь день |
| `end_datetime_str` | string? | Необязательное время окончания для интервала (например «11»); без него запись создаётся на одну точку времени (Apple Календарь: начало + 1 час) |
| `description` | string? | Необязательное описание |

### delete_schedule
Удаляет запись. Поддерживает точное совпадение по ID или нечёткое — по ключевому слову заголовка.

| Параметр | Тип | Описание |
|------|------|------|
| `schedule_id` | string? | ID записи (точное совпадение) |
| `title_keyword` | string? | Ключевое слово заголовка (нечёткое совпадение, например «встреча», «планёрка») |

### list_schedules
Показывает список записей.

| Параметр | Тип | Описание |
|------|------|------|
| `days` | int? | За сколько последних дней показать записи, по умолчанию 7 дней |

### update_schedule
Изменяет запись. Заголовок, время и описание можно обновлять по отдельности или вместе.

| Параметр | Тип | Описание |
|------|------|------|
| `schedule_id` | string? | ID записи (точное совпадение) |
| `title_keyword` | string? | Ключевое слово заголовка (нечёткое совпадение) |
| `new_title` | string? | Новый заголовок |
| `new_datetime` | string? | Новое время; форматы те же, что у `datetime_str` |
| `new_end_datetime` | string? | Новое время окончания для интервала (например «11»); указывается вместе с `new_datetime` |
| `new_description` | string? | Новое описание |
